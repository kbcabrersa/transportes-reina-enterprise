## Comportamiento

Operativo conserva las seis pestañas principales. Sus vistas internas son
Asignar jornada, Jornada actual e Historial y reconstrucción. Se reutiliza el
mapa Leaflet original. El planificador mantiene selección manual/grupal,
ayudantes, vehículo, ruta, barrio, orden por cercanía y estimaciones.

Cada fecha y nombre de operador normalizado tiene una asignación independiente.
Cambiar operador recupera su lista guardada. Las listas aún no guardadas no se
persisten al cambiar de operador. Los guardados bloquean doble clic y usan
transacciones. Las asignaciones antiguas con solo piloto se pueden consultar y
actualizar reutilizando su documento. No se eliminan documentos previos; si ya
existían duplicados históricos, no se borran ni fusionan automáticamente.

Jornada actual cruza exclusivamente identidad: UUID principal, clienteId como
respaldo cuando falta UUID, nunca nombre. Usa el último ATENDIDO/NO_ATENDIDO del
cliente en la fecha America/Guatemala, incluso si procede de otro operador: el
responsable mostrado es el de la asignación. Inactivo prevalece en esta vista.
Avance = (atendidos + no atendidos) / activos asignados × 100; cero sin activos.

La reconstrucción filtra opcionalmente el operador exacto normalizado, ordena
por primera aparición y conserva el último estado de cada cliente. Incluye
clientes actualmente inactivos si tienen eventos: su resultado histórico sigue
siendo ATENDIDO/NO_ATENDIDO. Conserva todos los IDs de eventos utilizados y mide
inicio/final con ellos. Para guardar se debe seleccionar un operador conocido;
la consulta sin filtro permite ver eventos sin operador sin inventar identidad.

Los puntos usan GPS maestro actual, con coordenadas válidas. Quien no tiene GPS
aparece en tabla, nunca como punto inventado. La línea y distancia Haversine son
aproximadas, no tracking real; el aviso aparece en la reconstrucción. No hay
seguimiento continuo ni Snap-to-Road. Recargar eventos actualiza tabla y mapa.

## Modelo final: jornadas_operativas

| Campo | Formato / significado |
| --- | --- |
| id | ID documental; nuevo: `operativo_` + SHA-256 de JSON `[fecha, operadorId, tipo]`. |
| fecha | Fecha calendario válida `YYYY-MM-DD`, día Guatemala. |
| operadorId | Nombre normalizado: minúsculas, sin acentos, espacios compactados. Provisional, no UID Firebase. |
| operadorNombre, piloto | Mismo nombre, espacios normalizados; piloto conserva compatibilidad. |
| tipo | ASIGNACION o RECONSTRUIDA. |
| estado | ASIGNADA para asignación; CERRADA para reconstrucción. |
| ayudantes, vehiculo, ruta | Texto; vacío si no se suministra. |
| barrios | Lista de textos no vacíos; puede estar vacía. |
| clienteIds | Lista no vacía de identidades, sin IDs vacíos ni duplicados. |
| ordenClienteIds | Mismos IDs, en orden de recorrido. |
| cantidadClientes | Longitud de clienteIds. |
| distanciaKmEstimada | Número finito no negativo; Haversine en km. |
| minutosEstimados | Número finito no negativo; en reconstrucción `(fin-inicio)/60000`. |
| usuario | Autor de escritura, actualmente enterprise. |
| createdAt | Timestamp servidor, conservado al actualizar. |
| updatedAt | Timestamp servidor en cada escritura. |
| eventoIds | Solo reconstrucción: IDs de todos los eventos usados. |
| atendidos, noAtendidos | Solo reconstrucción: enteros; suman cantidadClientes. |
| inicio, fin | Solo reconstrucción: milisegundos, mismo día Guatemala, fin >= inicio. |

El servicio valida fecha, operador, listas, orden y números, además de la
consistencia del resumen reconstruido. No expone eliminación de jornadas.
Las claves incluyen tipo para que reconstruir nunca sobrescriba la asignación.
Documentos antiguos conservan su ID mediante la transacción de actualización.

## Límites que dependen de Android

No se probó sincronización en teléfono. El gateway inspeccionado publica usuario,
pero la atribución requiere que coincida con el nombre operativo; sin directorio
no se distinguen homónimos ni renombres. Eventos sin identidad maestra resoluble
no reconstruyen visitas. Android debe publicar clienteUuid para evitar ambigüedad
entre IDs locales de dispositivos. No se implementó consumo Android de las
asignaciones ni confirmación de recepción. La identidad provisional está separada
como operadorId para sustituirla por UID en una fase posterior.

La recarga es manual, no una suscripción en vivo. Para cargar una reconstrucción
se vuelven a consultar los eventos referenciados y coordenadas maestras actuales;
no se guarda una fotografía histórica del GPS ni de los nombres. Las lecturas
siguen siendo de colecciones completas, como en el servicio existente.
